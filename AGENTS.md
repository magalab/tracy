# Tracy Engineering Guidelines

- Keep the default deployment model as one Go binary backed by two SQLite files.
- Keep metadata and trace storage independent. Do not expose SQL wrappers to the business layer.
- Do not use HTTP DTOs as domain objects or storage entities.
- Every new endpoint must have a black-box contract test. Every new storage backend must reuse the same contract and benchmark suites.
- Keep `docs/openapi.yaml` and the black-box contract tests in sync with every HTTP endpoint change.
- Ingest success means that the payload entered the bounded in-memory queue, not that it was persisted. A full queue must return an identifiable error.
- Store API key hashes only. Deliver a newly generated plaintext key exactly once, at creation time.
- Do not introduce Redis, message queues, ClickHouse, MinIO, or distributed locks unless the architecture is explicitly revised.
- If the default Go cache is not writable, set `GOCACHE` to a writable cache directory when running Go commands.

## Web assets

- Frontend source lives in `web/`.
- `internal/web/dist/` is generated by Vite and embedded into the Go binary; it is ignored by Git.
- Run `make build-web` before compiling the Go binary. `make build` performs both steps.
- Do not add a placeholder such as `.gitkeep` to `internal/web/dist/`; the directory must contain the real build output.

## Build and verification

- Run `make web-check` for frontend formatting, linting, TypeScript, and Vite build checks.
- Run `make test` and `make vet` for backend verification.
- Run `make build` to produce the local binary.
- Run `make docker-build` to build the container image locally.
